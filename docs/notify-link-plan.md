# 주행 종료 문자 링크(모의 발송) + 가입 없는 원터치 신고

- 작성: 2026-11-15 / 담당: 정현우 / 상태: 구현 완료 (서버 테스트 67개 통과, 화면은 Streamlit 테스트 도구로 확인, 브라우저 직접 확인 전)
- 기준 코드: `be/new-schema` (PR #20). 브랜치 `be/notify-link`.
- **모든 발송은 모의 발송이다.** 실제 메일·문자·카카오 발송은 만들지 않고, 만들 수 있다고 가정하지도 않는다. 서버가 "보낼 문자"를 DB에 저장하고, 화면의 메시지함이 그것을 문자처럼 보여 준다.

## 1. 요구사항

1. 주행이 끝나면(`POST /api/v1/trips/{id}/end`) 그 차량 주인에게 모의 문자를 만든다. 확인 목록이 1건 이상일 때만 만든다.
2. 문자에는 그 시민 전용 링크가 들어 있다. 링크를 열면 로그인·시민 선택 없이 그 시민의 확인 목록이 뜨고, [신고] 한 번으로 신고서가 만들어진다.
3. 가입 화면은 만들지 않는다. 전화번호는 "기기 초기 설정 때 한 번 등록된 것"으로 가정하고, 시연에서는 시민 3명에 가짜 번호를 미리 넣는다.
4. 시연 영상에서 문자가 오는 모습을 보여 줄 수 있어야 한다(메시지함 화면).

## 2. 결정 사항

| 번호 | 결정 | 이유 |
|---|---|---|
| N1 | 링크의 토큰이 신원 확인을 대신한다 | 가입·로그인 없이 원터치가 되려면 링크 자체가 열쇠여야 한다 |
| N2 | 토큰은 (주행, 시민) 한 쌍에 하나, 유효 72시간 | 링크가 새어도 영향이 제한된다 |
| N3 | 발송 추상화(Notifier)를 두지 않는다. 문자 행을 DB에 저장하는 것이 발송이다 | 실제 발송을 만들지 않으므로 겹을 더할 이유가 없다 |
| N4 | 스키마 변경은 `003_notify.sql`로, 이미 있는 DB에도 겹쳐 적용되게(멱등) 한다 | DB를 지우지 않고 올릴 수 있다 |
| N5 | `contracts/`(박겸과 공동)는 건드리지 않는다 | 블랙박스가 보내는 형식은 그대로다 |
| N6 | 기존 시민 선택 화면(확인·신고)은 개발·관리용으로 남긴다 | 시연 동선만 링크로 바꾼다 |

## 3. 데이터 변경 (`server/sql/003_notify.sql`, 멱등)

- `users.phone text`: 기기 설정 때 등록된 연락처(시연은 가짜 번호 010-0000-0001~3).
- `notifications`: `id`, `user_id`, `trip_id`, `to_phone`, `body`(링크 포함 문구), `token`(unique), `created_at`, `expires_at`, `opened_at`. `UNIQUE (trip_id, user_id)`로 한 주행에 한 번만 보낸다.
- 토큰은 평문으로 저장한다(메시지함이 링크를 다시 보여 줘야 한다). 실제 발송을 붙이는 일은 범위 밖이다.
- `init_db()`는 001을 (스키마가 없을 때만) 적용한 뒤 002를 항상 적용한다. `docker-compose.yml`은 `./server/sql`을 마운트하므로 새 DB에서는 둘 다 실행된다.

## 4. API 변경 (`server/main.py`)

| 변경 | 내용 |
|---|---|
| `POST /trips/{id}/end` | 응답은 그대로. 끝난 뒤 그 차량 주인의 확인 목록이 1건 이상이고 이 (주행, 시민)의 문자가 없으면 문자 행을 만든다 |
| `GET /m/{token}/findings` | 토큰 주인의 그 주행 확인 목록. 만료 410, 없는 토큰 404. 처음 열 때 `opened_at` 기록 |
| `POST /m/{token}/defects/{defect_id}/report` | 본문 없음. 시민은 토큰에서 정한다. 그 시민의 pending 항목에 없는 결함이면 404, 이미 신고됐으면 409 |
| `POST /m/{token}/defects/{defect_id}/skip` | 넘기기 |
| `GET /m/{token}/reports/{report_id}` | 방금 낸 신고서(그 토큰 주인 것만) |
| `GET /notifications` | 최근 문자 목록(전화번호는 가운데를 가림). 메시지함 화면이 쓴다 |
| `report_defect` | 본문을 `_do_report(conn, user, defect_id)`로 빼서 기존 API와 토큰 API가 같이 쓴다 |

## 6. 완료 기준

자동 테스트(`pytest server`):
1. 결함이 있는 주행을 끝내면 그 차량 주인에게 문자가 정확히 1건 생기고 문구에 링크와 건수가 들어 있다.
2. 결함이 없는 주행을 끝내면 문자가 없다.
3. 같은 주행을 두 번 끝내도 문자는 1건이다.
4. 토큰으로 목록을 조회하면 그 시민의 항목만 나온다.
5. 토큰으로 신고하면 신고서 1건이 생기고 결함이 `reported`가 된다. 다시 신고하면 409. 같은 결함을 기다리던 다른 시민의 항목은 `already_reported`가 된다.
6. 만료된 토큰은 410, 없는 토큰은 404.
7. 토큰 주인의 목록에 없는 결함을 신고하면 404.
8. 서로 다른 시민의 토큰 두 개로 같은 결함을 동시에 신고하면 신고서 1건.
9. `GET /notifications`의 전화번호는 가운데가 가려져 있다.
10. `003_notify.sql`을 이미 적용된 DB에 다시 적용해도 오류가 없다.
11. 기존 테스트가 그대로 통과한다.

눈으로 확인(브라우저):
12. 메시지함에 문자가 뜨고, 링크를 누르면 로그인 없이 확인 화면이 열린다.
13. [신고] 한 번으로 신고서 요약이 같은 화면에 나온다.
14. 관리자 지도에서 그 결함이 "신고됨"으로 바뀐다.
15. 링크 화면에 사이드바·시민 선택·관리자 메뉴가 보이지 않는다.

## 7. 위험과 한계 (발표에서 밝힐 것)

| 위험 | 대응 |
|---|---|
| 링크가 새면 남이 신고를 누를 수 있음 | 72시간 만료, 모의 제출. 한계로 밝힌다 |
| Streamlit이 다시 그릴 때 주소의 `t`가 사라짐 | 처음 읽을 때 `st.session_state`에 저장 |
| 주행 종료 뒤 다른 차량 관측으로 새로 노출 기준을 넘는 결함은 문자가 다시 가지 않음 | 한 주행에 한 번만 만든다. 그 결함은 시민 선택 화면 목록에는 나온다 |
| 전화번호는 개인정보 | 시연은 가짜 번호만, 메시지함은 가운데를 가린다 |
| 실제 발송이 없음 | 모의 발송임을 발표에서 밝힌다 ("문자 대행사 API를 붙이면 같은 자리에서 보낼 수 있다"는 설명까지만) |

## 8. 범위 밖

가입·로그인·기기 등록 화면, 실제 메일·문자·카카오 발송, `vehicles` 테이블 제거, uuid 변경, 클립 업로드, 포상 도로 GeoJSON.
